# Knapsack 0/1 / 0/1 ナップサック問題

**難易度**: Medium

## 概要

0/1 ナップサック問題は、重さと価値を持つ n 個のアイテムから、容量 W 以下の重さになるように選び、価値の合計を最大化する最適化問題である。各アイテムは「選ぶ（1）か選ばない（0）か」の2択（0/1 制約）であり、分割は不可。動的計画法で O(nW) 時間・空間で解ける。

## アルゴリズムの直感

**dp[i][w] の意味**: 「最初の i 個のアイテムだけを使い、容量 w のナップサックに入れられる最大価値」

状態遷移の核心は「i 番目のアイテムを入れるか入れないか」の2択：

1. **入れない**: dp[i][w] = dp[i-1][w]（i 番目を無視して前の状態そのまま）
2. **入れる（weight[i] <= w の場合）**: dp[i][w] = dp[i-1][w - weight[i]] + value[i]
   - 「容量 w から i 番目の重さを引いた状態での最大価値」に i 番目の価値を足す

この2択の大きい方が dp[i][w] になる。最終答えは dp[n][W]。

Cormen et al. (2022) は「0/1 ナップサックは最適部分構造と重複する部分問題を持つため、動的計画法が適用できる」と解説している。

## 自分の解釈

最初は「なぜ 2D テーブルが必要なのか」が分からなかった。重要なのは「i 番目を入れる場合に dp[i-1][w - weight[i]] を参照する」点で、前の行（i-1 行）の値を変えずに参照する必要があるため 2D にする（または 1D の場合は逆順ループが必要）。

グリーディ法（価値/重さ比が高いものから選ぶ）が「分数ナップサック」では最適解だが、0/1 ナップサックでは最適解にならないことがある。これは「アイテムを分割できない」制約が最適部分構造を壊すため。

## 計算量

- 時間: O(nW)（n = アイテム数、W = 容量）
- 空間: O(nW)（2D DP テーブル。1D 最適化で O(W) にできる）

## Example

```
アイテム: [{w=2,v=6}, {w=2,v=10}, {w=3,v=12}], 容量=5

dp テーブル（行: i番目のアイテム使用可否、列: 容量）:
     w=0  w=1  w=2  w=3  w=4  w=5
i=0:  0    0    0    0    0    0   (アイテムなし)
i=1:  0    0    6    6    6    6   (w=2,v=6 を使える)
i=2:  0    0   10   10   16   16  (w=2,v=10 を使える)
i=3:  0    0   10   12   16   22  (w=3,v=12 を使える)

dp[3][5]=22 が答え（アイテム2と3を選択: v=10+12=22, w=2+3=5）

状態遷移の詳細（i=3, w=5）:
  入れない: dp[2][5] = 16
  入れる:   dp[2][5-3] + 12 = dp[2][2] + 12 = 10 + 12 = 22
  max(16, 22) = 22
```

## 実装メモ

- `capacity+1` サイズの配列で w=0 から w=capacity まで計算する（0-indexed で扱いやすい）
- `dp[i][w] = dp[i-1][w]` の初期代入により、「入れない」ケースをデフォルトとして扱える
- 1D 最適化: 外側ループを i、内側を w=capacity から w=weight[i] まで逆順にすると O(W) 空間で解ける
