# Quick Sort / クイックソート

**難易度**: Medium

## 概要

クイックソートは分割統治法に基づく比較ソートアルゴリズムである。配列からピボット要素を選び、ピボットより小さい要素・等しい要素・大きい要素の3グループに分割し、小さいグループと大きいグループを再帰的にソートして結合する。平均計算量は O(n log n) だが、ピボット選択が最悪の場合は O(n²) になる。

## アルゴリズムの直感

クイックソートが機能する理由は「ピボットを境にした分割」が確実に配置を絞り込むことにある。ピボットより小さい要素は必ず左側、大きい要素は必ず右側に収まる。この性質により、各再帰呼び出しは「ピボットの最終位置が確定した部分問題」へと縮小していく。

**ピボット選択戦略**:
- **先頭・末尾**: 実装が簡単だが、既ソート済み配列で O(n²) になりやすい
- **中央要素（本実装）**: 既ソート済み・逆順配列に対して安定した性能を示す
- **ランダム**: 最悪ケースを確率的に回避できる（競技プログラミングで多用）
- **Median-of-Three**: 先頭・中央・末尾の中央値。最悪ケースを実用的に回避する

Sedgewick & Wayne (2011) は「ランダムシャッフル後の先頭要素をピボットとする」実装を標準として紹介している。これにより既ソート済み入力での O(n²) を回避しつつ実装をシンプルに保てる。

## 自分の解釈

最初に「なぜバブルソートより速いか」を理解しにくかった。バブルソートは隣接要素の比較を毎回全体に渡って行うのに対し、クイックソートはピボットによって「探索範囲を半分に絞り込む」操作を再帰的に行う。この点でバイナリサーチと同じ「問題を半分に割る」発想が根底にある。

重複要素を含む場合の実装は注意が必要で、ナイーブな2分割（< と >=）では重複が多い配列で偏った分割になる。本実装は `< pivot`, `== pivot`, `> pivot` の3分割を採用し、重複が多い場合でも均等な分割が保たれる。

## 計算量

- 時間: O(n log n)（平均）、O(n²)（最悪: ピボットが常に最小/最大値の場合）
- 空間: O(log n)（再帰スタック、平均）、O(n)（最悪）

## Example

```
入力: [3, 1, 4, 1, 5]
ピボット: 4（中央要素、インデックス 2）

分割:
  left   = [3, 1, 1]  (< 4)
  middle = [4]        (== 4)
  right  = [5]        (> 5)

再帰: QuickSort([3, 1, 1])
  ピボット: 1（中央要素）
  left   = []
  middle = [1, 1]
  right  = [3]
  → [1, 1, 3]

再帰: QuickSort([5])
  → [5]

結合: [1, 1, 3] + [4] + [5] = [1, 1, 3, 4, 5]
出力: [1, 1, 3, 4, 5]
```

| ステップ | left       | middle | right | 結果候補 |
|--------|-----------|--------|-------|--------|
| 1      | [3, 1, 1] | [4]    | [5]   | -      |
| 2      | []        | [1, 1] | [3]   | -      |
| 3      | -         | -      | -     | [1,1,3,4,5] |

## 実装メモ

- 本実装は「フィルタ方式」で新しい配列を生成するため空間計算量が O(n log n) になる。インプレース実装は O(log n) だが実装が複雑
- `arr.length <= 1` のベースケースで空配列と単一要素を同時に処理できる
- 3分割（left/middle/right）により重複要素が多い配列でのパフォーマンス劣化を防ぐ
