# DFS / 深さ優先探索

**難易度**: Medium

## 概要

グラフの開始ノードから、一本道をできる限り深く進んでから引き返し、未訪問の分岐を探索するアルゴリズム。再帰（またはスタック）を使って「深さ方向への優先」を実現する。サイクル検出・トポロジカルソート・連結成分の列挙などに活用される。

## アルゴリズムの直感

迷路をたどるイメージ。行き止まりに達するまで同じ方向に進み続け、行き止まりに当たったら直前の分岐点に戻って別の道を試す。訪問済みセットが「来た道に印をつける」役割を果たし、無限ループを防ぐ。

再帰を使う場合、コールスタック自体がDFSのスタックとして機能する。これがBFSとの実装上の最大の違いである。

## 自分の解釈

BFS との対比で覚えやすい：BFS は「同じ距離のノードを全部処理してから次へ」、DFS は「一本道を最後まで進んでから戻る」。

再帰実装は簡潔だが、グラフが非常に深い場合にスタックオーバーフローが起きる。その場合は明示的なスタック（配列）を使ったイテレータ版が堅牢だが、今回は可読性を優先して再帰で実装した。

訪問順は隣接リストの順序に依存するため、同じグラフでも実装によって異なるトラバーサル順になりうる点に注意。

## 計算量

- 時間: O(V + E)（V: ノード数、E: 辺数）
- 空間: O(V)（visited セットと再帰スタックの深さ）

## Example

```
グラフ:
  1 → [2, 3]
  2 → [4]
  3 → [4]
  4 → []

start = 1

visit(1): visited={1}, result=[1]
  visit(2): visited={1,2}, result=[1,2]
    visit(4): visited={1,2,4}, result=[1,2,4]
      隣接なし → return
    return
  visit(3): visited={1,2,3,4}, result=[1,2,4,3]
    visit(4): すでに visited → スキップ
    return
  return

出力: [1, 2, 4, 3]
```

## 実装メモ

- `visited[node] = true` をノードを処理する前（pushの前）に行う。後回しにすると閉路グラフで無限再帰になる
- Go の変数束縛クロージャ `var visit func(node int); visit = func(...) {...}` は再帰クロージャの標準的な記法
- グラフに存在しないノードへの `graph[node]` アクセスは Go ではゼロ値（nil スライス）、TypeScript では `Map.get()` が `undefined` を返すため `?? []` でフォールバックする
